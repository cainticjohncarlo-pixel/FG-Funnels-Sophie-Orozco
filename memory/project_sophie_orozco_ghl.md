## Platform gotchas found by testing, do not re-derive

- **No date arithmetic.** `plus_time`, `date_add` and the `date` filter all return empty.
  `{{right_now}}` resolves to an object and stores as `[object Object]`. Use the native
  **"Current Date"** option on date fields instead. Program end dates cannot be predicted,
  so emails carry a hardcoded countdown and the end date is stamped on completion.
- **Cloudflare blocks urllib's default user-agent** with a 1010. Send `curl/8.0.1`.
- **Custom field create** wants `options`; the read endpoint returns `picklistOptions`.
- **If/Else caps at 10 branches.** Chain a second If/Else off the "None" path for more.
- **If/Else branches never rejoin**, so long sequences must live in a separate workflow.
- **Tag and field pickers cache** in the workflow builder; API-created items need a hard
  refresh, and tag pickers may hide tags never applied to any contact.
- **Remove From Workflow only lists published workflows**, so stop-workflows must be
  wired after the journeys go live.
- **Calendly-synced appointments cannot be updated via API.** `PUT /calendars/events/appointments/{id}` returns 400 "Calendly calendars are not supported for this operation". Status changes (Invalid etc.) must be done in the GHL UI. Contacts can still be removed from workflows and reassigned by API (`execution/ghl_fix_double_booking.py`).
- **A lead who books a second call is a NEW appointment, not a reschedule**: booking-triggered sequences (WF-VALUE, `Call Booked Sequence > SMS`) re-fire. Fix design: once-only tag gate (`precall-sequence-sent`, `precall-sms-sent` placed after the confirmation text); Re-Entry stays ON for reminders.
- Contacts/search **504s on long paging runs** - retry 429 and 5xx with backoff.
